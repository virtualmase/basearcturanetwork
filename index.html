Gateway primitives

Separate identity, evidence, and payment gates.

The testnet is a place to validate a narrow interaction at a time. It is not a reason to combine wallet control, task authority, marketing claims, and payments into one opaque system.

01

Mandate

An operator declares a limited capability scope and an on-chain identity reference. A wallet address is an identifier, not a credential or permission to transact.

02

Task

An organization describes the scope, evidence standard, and guardrail before a task is surfaced. Unreviewed work does not become public work.

03

Receipt

A reviewed receipt connects the source, work, mandate, and decision. It documents a bounded contribution; it is not a financial return statement.

Non-negotiable boundary

Test an interaction. Do not transfer trust blindly.

The testnet gateway exists to make controls visible before any production decision. It deliberately fails closed when configuration or authorization is missing.

×No seed phrase, private key, login credential, or wallet custody is requested by this site.
×No token sale, yield, return, earnings, or investment representation is made here.
×No automatic payout, task acceptance, publishing, or autonomous on-chain action is enabled from this gateway.
→Any later testnet payment requires a named receiver, a configured facilitator, a capped resource, and explicit approval for the specific test.
Builder path

Start small, preserve a receipt.

Use Base Sepolia in a wallet you control, follow Base’s current setup guidance, and begin with a narrowly scoped resource or evidence interaction. Do not treat testnet assets or early experiments as financial products.

NOTEPublic Base endpoints may be rate-limited and are not a production RPC plan. Persistent or production traffic requires a separately selected provider and security review.
01

Prepare your own test wallet

Select Base Sepolia in an EVM wallet you control. Use official documentation and a faucet of your choice; never share recovery material with an application or operator.

02

Inspect the resource boundary

Read the scope, price cap, network, and evidence requirement. Stop if any action asks for mainnet funds, unrestricted approval, or credentials.

03

Keep the evidence trail

Record the task, source, output, and reviewer decision. A test result is useful only when its assumptions and limits remain visible.
